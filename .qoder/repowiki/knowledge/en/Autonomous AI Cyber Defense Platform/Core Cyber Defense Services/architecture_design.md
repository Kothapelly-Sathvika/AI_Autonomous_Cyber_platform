All services are thin Python modules built on a single SQLite database defined in `database.py`, which is the only place schema creation (`init_db`) and CRUD helpers live. Other modules depend on it exclusively through `get_connection()` and helper functions rather than raw SQL: `incident_manager.py` handles incident search/update/export; `threat_intel.py` queries the `threat_intel` table for IP/domain lookups; `email_service.py` reads SMTP settings and recipient lists from `settings`/`email_recipients`; `alarm_service.py` plays Windows beeps for high/critical alerts; `threat_detection.py` owns an IsolationForest + RandomForest model persisted under `data/models/`; `simulator.py` generates synthetic attack events consumed by the rest of the pipeline. Cross-module communication is purely function-call based — there is no event bus or shared state object — so wiring happens at the application entry point where these modules are imported and their public APIs composed.
